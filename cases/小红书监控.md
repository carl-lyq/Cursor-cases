# 小红书话题监控

> 项目路径：`小红书监控` · 领域：内容研究 · 数据采集

**一句话**：本机偶尔运行，按关键词批量采集小红书公开笔记，AI 逐条总结后导出 CSV，并推飞书运行报告

## 业务背景

**谁在用**：本人（个人内容研究与选题观察）

**典型场景**：隔几天需要了解小红书上与**雅思学习**、**AI 编程工具**（Vibe Coding、Codex、Claude Code 等）相关的最新笔记，用于选题灵感与竞品/热点观察。

**要解决什么**：把「打开 App 搜词、翻帖子、抄链接、记互动数」变成**可重复执行的一次采集任务**——结果结构化入库、每条有中文摘要、本地 CSV 可分析、飞书收到批次洞察，而不是零散截图和收藏夹。

运行方式：**本机手动触发**（`python -m xhs_monitor run`），非 7×24 云端服务；使用专用小号扫码登录。

## 工作痛点

- 8 个监控词各需约 100 条笔记，手工浏览复制**不可行**
- 隔几天再跑时，需要**去重**并**刷新点赞/收藏/评论**，不能重复抄正文
- 搜到的笔记分散在 App 里，缺少统一表格（链接、正文、作者、话题标签）
- 读几十上百条笔记才能归纳热点，**缺少逐条 AI 摘要和批次总结**
- 跑完希望手机能收到结果，而不是再去翻本机文件夹

## 项目要做什么

从业务视角，本项目最终要交付的是：

**一条「配置 → 采集 → 总结 → 导出 → 通知」的本机流水线**，支撑个人选题研究。

### 监控什么（首期 8 个关键词）

雅思、vibe coding、雅思自学工具、手搓、codex、claude code、雅思自学网站、雅思自学软件（话题页能力保留，后续可增）。

### 需要什么输入

- `config/config.yaml`：监控词、排序、采集上限、过滤规则
- 小号扫码登录态（`data/session/`）
- 可选：LLM API Key、飞书 Webhook（未配置时采集与 CSV 仍正常，总结/推送跳过）

### 产出什么

| 产出 | 说明 |
|------|------|
| `data/db/xhs_monitor.db` | SQLite，笔记去重主键 + 互动数更新 |
| `data/export/*.csv` | 每次 run 结束自动导出，含**笔记链接**与 **AI 总结** |
| 飞书消息 | 运行统计 + 批次洞察（200–400 字）+ 新增笔记互动 Top 10 链接 |

### 关键能力

- **Playwright** 浏览器采集（后台无头，采一条存一条，中断不丢）
- **去重更新**：新笔记拉详情 + AI 总结；旧笔记仅刷新互动数
- **多路搜索与相关性过滤**（组合词拆分、`all`/`any` 匹配、过采重试）
- **混合详情模式**：列表全量 + 互动 Top N 慢速拉正文（平衡速度与 Web 端限制）
- **逐条 + 批次 LLM 总结**，失败不阻塞入库

### 明确不做（本期）

多用户后台、7×24 定时云跑、官方开放平台、评论明细/封面下载、飞书上传 CSV 附件。

## 工作方式对比

### 传统方式

在小红书 App 或网页里逐个搜词、翻 feed、手动收藏或复制；无法一次处理 8 词 × 100 条，也难以隔日只更新互动数而不重复劳动。

### 用 Cursor 之后

1. **可行性调研**：在对话中收敛路线（Playwright 本机采集 vs 官方 API / 第三方），明确合规与范围
2. **PRD 定稿**：监控词、去重策略、CSV/飞书、验收标准写入 `docs/PRD.md` 作为唯一真相源
3. **技术方案 + MVP 实现**：Agent 按 PRD 搭建 Python 包（采集、存储、总结、导出、通知）并完成试跑验证
4. **迭代调参**：搜索过滤、详情模式、间隔与进度提示等，继续以 PRD/优化清单驱动小步改

## 提效与业务价值

| 维度 | 传统方式 | 用 Cursor 后 |
|------|----------|--------------|
| **规模** | 手工难以覆盖 8 词 × 100 条/次 | 一次 `run` 可处理数百条并自动去重更新 |
| **结构化** | 收藏夹/截图，难分析 | SQLite + UTF-8 CSV（含 `note_url`、`summary`） |
| **洞察** | 靠人通读归纳 | 每条 AI 摘要 + 飞书批次总结与 Top 10 亮点 |
| **立项到 MVP** | 需自行调研、写 PRD、搭爬虫骨架 | 文档与可运行代码主要在 Cursor 对话中快速落地 |

- **谁直接受益**：本人（选题与内容研究）
- **成本**：采集侧无第三方 API 费；LLM 按新笔记条数计费；单次全量 run 约 **1–3 小时**量级（含间隔防风控）
- **合规边界**：仅公开内容、个人分析、专用小号自用
