# 使用手册

## 日常流程

### 1. 自动 / 手动扫描

**本机全量扫描**（推荐每周或完成重要协作后）：

```bash
python3 scripts/portfolio.py scan
```

**仅扫仓库与文档**（GitHub Action 使用，本机也可单独跑）：

```bash
python3 scripts/portfolio.py scan --repo-only
```

**仅补扫 Agent 对话**（例如刚出差回来）：

```bash
python3 scripts/portfolio.py scan --transcripts-only
```

### 2. 查看待确认

```bash
python3 scripts/portfolio.py status
```

打开 [reviews/LATEST.md](../reviews/LATEST.md)，阅读：

- 新增了哪些案例
- 哪些案例有更新
- 哪些数字需要人工核实

### 3. 确认发布

见 [03-确认发布流程.md](./03-确认发布流程.md)。

## 提高案例质量

自动合成能生成 70% 可用的初稿。要变成高质量汇报材料，建议在项目里维护事实卡片：

**路径**：`<子项目>/.cursor/ai-impact.yaml`  
**模板**：[templates/ai-impact.example.yaml](../templates/ai-impact.example.yaml)

填写后下次 `scan` 会优先使用你写的内容，尤其是：

- `traditional` — 以前怎么做
- `with_cursor` — Cursor 用法
- `impact` — 量化提效、新突破

## 忽略测试项目

编辑 `state/case-status.json`，将项目状态设为 `ignored`：

```json
{
  "test_course-marketing-rhetoric": { "status": "ignored" }
}
```

## 电脑关机 / 离线

- GitHub Action 仍会更新 **repo 部分** 草稿
- Agent 对话需本机追平；下次 `scan` 会自动处理积压
- 详见 [04-GitHub与分支策略.md](./04-GitHub与分支策略.md)

## 常见问题

**Q：案例卡太「空」？**  
A：补充 `.cursor/ai-impact.yaml`，或确保项目根目录有 `PRD.md` / `README.md`。

**Q：对话没归到正确项目？**  
A：Cursor 工作区路径映射可能失败；检查 `inbox/*-scan.json` 的 `unmapped_count`，必要时在 yaml 里手写 `project` 字段。

**Q：能否直接改 cases/*.md？**  
A：可以，但下次 `scan` 可能覆盖。长期事实应写在 `ai-impact.yaml`；`locked` 状态可保护已定稿案例。
