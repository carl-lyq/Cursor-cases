# 确认发布流程

## 原则

- **自动扫描** → 只更新 `draft/`、`cases/`、`reviews/`
- **你确认之后** → 才更新 `published/`
- **GitHub `main` 分支** → 与 `published/` 同步（备份）

未确认前，请勿将 `draft/` 用于对外汇报。

## 方式一：Cursor 对话确认（推荐）

在 **Cursor 案例库** 或任意已加载本仓库的会话中说：

```
确认 portfolio
```

或指定项目（与案例卡中的项目路径一致）：

```
确认 portfolio Miscs/押题班画像
确认 portfolio course-marketing-rhetoric
```

Agent 应执行：

```bash
cd "/Users/mac/Library/CloudStorage/OneDrive-个人/AI Projects/Cursor案例库"
python3 scripts/portfolio.py confirm --cases <项目名>
# 或全部：python3 scripts/portfolio.py confirm
```

然后将 `published/` 与 `state/` 变更 commit 并 push 到 GitHub `main`。

> 规则已写入 [.cursor/rules/portfolio-confirm.mdc](../.cursor/rules/portfolio-confirm.mdc)

## 方式二：命令行确认

```bash
python3 scripts/portfolio.py confirm
python3 scripts/portfolio.py confirm --cases Miscs/押题班画像
```

确认后手动 push：

```bash
git add published/ state/
git commit -m "portfolio: confirm cases"
git push origin main
```

## 确认前检查清单

- [ ] 已阅读 `reviews/LATEST.md`
- [ ] 「待核实」中的数字已核对或已删减
- [ ] 案例语气适合对外（无内部敏感信息）
- [ ] 项目名称、背景描述准确

## 定稿锁定

汇报材料定稿后，在 `state/case-status.json` 将对应项目设为 `locked`，后续自动扫描不会覆盖该案例正文。

## 发布后的文件

| 文件 | 用途 |
|------|------|
| `published/AI-Projects-Portfolio.md` | 总览目录，汇报首选 |
| `cases/<id>.md` | 单项目完整案例（confirmed 项目收录进总览） |
